When does an offline signal deserve a robot run?

A transparent way to turn Generalist's published data-mixture measurements into the next controlled, decision-ready experiment.

Cathy Liu · University of Melbourne

Question Offline screen Robot experiment Methods

Generalist's GEN-0 report compares eight physical-data mixtures across dexterity, applications, and generalization. The interesting result is not a universal winner. It is a set of metric conflicts that can make the next real-robot comparison more informative.

I built this brief to make that handoff explicit: screen the published measurements, expose the priority rule, then generate a blinded A/B protocol with a visible rollout budget.

The decision

Which two data mixtures should earn the next scarce robot-evaluation slots, and what would make the result believable? Offline action-prediction metrics can nominate a contrast. They cannot establish real-world task success by themselves.

2. Convert the conflict into a robot experiment

Recommended contrast
Applications: B · Class 2 skills vs A · Class 2 + 3

One candidate leads on prediction error; the other leads on reverse KL. That disagreement is a reason to test, not a reason to average the metrics into certainty.

Primary decision

Does the candidate prioritized by the current offline rule improve preregistered task success under held-out physical conditions?

Controls

Blind the evaluator; counterbalance model order; block by robot, end effector, object pose, material lot, operator, and time block.

Secondary outcomes

Completion time, interventions, recovery attempts, failure mode, and invalid-run reason. Report each condition before pooling.

Stop rule

Use the planned sample size. Do not stop on a favorable interim streak. Preserve excluded runs and their reasons.

Plan the rollout budget

Set the control success rate and the smallest absolute improvement worth detecting. The calculator uses a two-sided 5% test and 80% power with an equal-size normal approximation.

Methods and limits

The source table contains three validation prediction-error values and three reverse-KL values for each of eight data mixtures. This page computes task-specific ranks and a user-controlled weighted screen directly in the browser. The reproducible CSV, analysis script, and tests are included in the public repository.

The reported table has no sample sizes, uncertainty intervals, raw trajectories, or real-robot outcomes for each mixture. Therefore the screen only prioritizes experiments. The sample-size calculation is approximate and should be replaced by a preregistered design that accounts for repeated robots, tasks, and clustered conditions when those data are available.

Why I built this

I am strongest where careful physical execution meets quantitative reasoning: maintaining protocol discipline, documenting conditions, checking whether a result survives controls, and turning an analysis into the next experiment. I have not operated Generalist's robots; this is a compact demonstration of how I would reason about their evaluation.
